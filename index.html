WHO WRITES THE CODE
You write every line. Three steps.
01 · MANUAL MODE

Write it yourself. The agent is switched off.

Flip a workspace to Manual and the agent cannot start: haro refuses every run. You write it, run the tests and ship it. The built-in editor has a file tree, search, tabs, split view and a terminal, right next to your tests.

Lines the passing suite actually ran get a small mark in the gutter, so you can see what is covered while you write.

02 · THE ASSISTANT

An assistant that helps you think, not type.

PLANchecklist
SEARCHpointers
AI EDITS0 inside haro

In Manual mode haro's assistant can read your code, your git history and the web, and nothing else. Ask for a plan and you get a checklist with the reason for the order. Ask where something lives and it points you to the file, the commit or the docs. Code in its answers is stripped, so it points and you write.

haro compares your files before and after every answer, so "AI edits: 0" is checked, not claimed. If something else was writing at the same moment, it says "unverified" instead.

03 · THE FENCE

Hand the agent only what you name.

Type the files it may edit into the Scope box under the prompt. If it reaches outside them, haro usually refuses the edit before it is written and tells the agent why. Whatever still lands outside (a shell command can do that) is put back when the run ends, and what the agent wrote there is kept aside, so nothing is lost.

Your own uncommitted work is never touched. The fence is opt-in: an empty Scope box means no fence, and the receipt says so.

04 · REVIEW

Read what ships before it ships.

The Review step opens on an overview: what was asked, how far the agent was allowed to go, and how big the change is, with a plain estimate of how long it takes to read well. Then the files, riskiest first: lines no test ran, new dependencies, a weaker test, a possible secret.

Mark each file Viewed and it folds away. Once every file is viewed and the tests are green, Proceed to ship unlocks. haro keeps count of what you marked and how long each diff was open, and puts it on the receipt as a plain fact, never as "reviewed".

05 · SHIP WITH A RECEIPT

A receipt that says who wrote what.

You can only merge on green. The pull request gets a receipt: the test results, the fence the agent ran under, the tamper check, how the diff was read, and an honest answer to who wrote the code. Files you edited yourself, in any editor, are listed, so it only says "you and the agent" where that is true.

It describes what happened inside haro. It cannot see another AI tool open beside it, so it never says "no AI wrote this".

06 · THE GATE

Underneath it all, your tests decide.

The safety net is quiet and automatic. Green means your own test suite passed, on your own machine, and no model gets a vote. If a test gets deleted, skipped or quietly loosened, the tamper alarm catches it, and the merge stays blocked until the suite is green again.

Lines no test ran are marked in the diff, so a big change shrinks to the part nothing checked.

07 · AGENT MODE

Hand over the wheel when you just need it shipped.

Switch the workspace to Agent and describe the task. The agent works in its own copy of your repo, several at a time if you like, and the same fence, gate and receipt apply. It can hand lookups and reviews to sub-agents on cheaper models you choose.

Every run keeps a restore point, so one button puts your files back to before it started. A short block-list refuses the worst shell commands, such as git reset --hard and reading your .env, and the receipt lists anything it refused. You can switch to Manual halfway: haro saves your part first, so the receipt shows you both.

08 · DASHBOARD

See what needs you, at a glance.

Every workspace across your projects in one list, sorted by what it needs: your review, still running, ready to ship, or done. Each row shows the next step. The line under the heading counts the changed lines waiting for you, and a review limit you set warns you when agent output is piling up faster than you can read it.

09 · XP

A small pat on the back for doing it yourself.

Levels, ranks from Novice to Master, a streak and a few badges. Work you wrote by hand pays more than work an agent touched, and a red run pays nothing. It is a light scoreboard, and you can switch it off in Settings.

10 · LOCAL FIRST

Local first, Linux first.

Everything runs on your machine, against your own repo. The agent uses your own Claude Code login, and pull requests go through your own gh. No GitHub app to install, no broad permissions to hand over. There is a guide built into the app, so you can look things up without leaving it.
